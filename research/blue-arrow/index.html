Blue Arrow: orquestación local de acciones con control humano

Blue Arrow es un framework de orquestación local que permite controlar acciones de escritorio, terminal, navegador, sistema y documentos mediante una interfaz de Telegram. Su principio central es human-in-the-loop: la IA puede asistir en la interpretación y planificación, pero las acciones reales pasan por controles, aprobación, workers y verificación.

1. Problema que aborda

Las automatizaciones que interpretan instrucciones en lenguaje natural y ejecutan acciones sobre un equipo pueden producir efectos no deseados si la interpretación, la autorización y la ejecución quedan mezcladas. Blue Arrow aborda ese problema separando la recepción de comandos, la planificación, los controles de seguridad, la aprobación, el enrutamiento a workers y la comprobación del resultado.

2. Objetivo y casos de uso

El objetivo es ofrecer una capa local y modular para coordinar tareas asistidas por IA sin entregar a la IA la autoridad final sobre las acciones. Los casos de uso descritos en el repositorio incluyen:

  • Control de aplicaciones locales mediante Telegram o CLI.
  • Ejecución de acciones aprobadas en terminal y sistema.
  • Automatización de flujos de navegador mediante Playwright.
  • Búsqueda de archivos y consulta de información del sistema.
  • Generación y escritura de documentos mediante LibreOffice Writer.
  • Integración opcional con modelos locales mediante Ollama/LLaMA.

3. Arquitectura documentada

El sistema separa el runtime, los módulos y el blueprint declarativo. El runtime central, desarrollado en Node.js, descubre módulos y enruta mensajes. Los módulos especializados pueden estar implementados en Node.js o Python. La topología y sus conexiones se declaran en blueprints/system.v0.json.

ComponenteResponsabilidad descrita
Runtime (Node.js)Bootstrap, descubrimiento de módulos, enrutamiento, gestión de procesos y logging.
Blueprint (JSON)Declara módulos y conexiones entre puertos.
Bus (JSON Lines)Intercambio de mensajes entre procesos mediante stdin/stdout.
Planner y AgentInterpretación y transformación de comandos en planes de acción.
Safety Guard y ApprovalControles y circuito de aprobación antes del enrutamiento de acciones.
Router y WorkersDistribución y ejecución de acciones especializadas.
Verifier Engine y SupervisorComprobación de resultados y coordinación del cierre de tareas.

El flujo de alto nivel documentado es:

Telegram / CLI
    → Planner
    → Agent
    → Safety Guard / Approval
    → Router
    → Workers (desktop / terminal / browser / system)
    → Verifier (cuando corresponde)
    → Supervisor
    → respuesta a la interfaz

La documentación técnica también establece comunicación por puertos declarados, mensajes JSON Lines y metadatos de trazabilidad como trace_id. El supervisor se describe como autoridad única para cerrar tareas, mientras los workers informan resultados y eventos.

4. Tecnologías y requisitos publicados

  • Node.js 20 o superior para el runtime.
  • Python 3.11 o superior para módulos y workers Python.
  • Telegram como interfaz de control.
  • Playwright para automatización del navegador.
  • Ollama/LLaMA como integración opcional de IA local.
  • LibreOffice Writer para el flujo de documentos descrito.

La configuración detallada, variables de entorno y dependencias deben consultarse en DEVELOPMENT.md, OLLAMA_SETUP.md y .env.example.

English version · Project technical brief

Blue Arrow: local action orchestration with human control

Blue Arrow is a local orchestration framework for controlling desktop, terminal, browser, system and document actions through Telegram. Its central principle is human-in-the-loop execution: AI may assist with interpretation and planning, while real actions pass through safety checks, approval flows, workers and execution verification.

Problem and objective

The project separates command intake, planning, safety checks, approval, worker routing and result verification. This separation is intended to reduce the risk of mixing natural-language interpretation with unrestricted execution. The human remains the final decision-maker.

Architecture

The repository documents a central Node.js runtime, specialized Node.js/Python modules, a declarative JSON blueprint and JSON Lines messaging over stdin/stdout. The high-level path is:

Telegram / CLI → Planner → Agent → Safety Guard / Approval
→ Router → Workers → Verifier (where applicable)
→ Supervisor → interface response

Documented workers cover desktop, terminal, browser and system tasks. The project also describes optional Ollama/LLaMA integration, Playwright browser automation, and LibreOffice Writer workflows.

Current status and limitations

The repository describes a migration from a token-based flow toward a state-driven architecture as work in progress. The target design must not be mistaken for a completed migration. Published tests, health checks and CI workflows are inspectable in the source repository; this page does not claim a fresh test run or independent security certification.
