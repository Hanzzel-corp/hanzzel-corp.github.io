SAT Engine: una colección evolutiva de solucionadores SAT

SAT Engine reúne implementaciones de generadores y solucionadores para el problema de satisfacibilidad booleana (SAT). El repositorio explora una progresión desde backtracking exhaustivo hasta búsqueda local estocástica y un backend híbrido C++/Python con paralelismo.

Código fuente · README · Arquitectura · Documentación de algoritmos

Precisión de versión: el repositorio se llama SAT-Engine-v7 y el README imprime “SAT Engine v7”, pero la tabla de versiones y la estructura documentan implementaciones hasta v5 (incluido el backend C++). El archivo de ejecución C++ también imprime v7. Esta ficha describe lo que el código y los documentos muestran; no presupone que exista una implementación v6/v7 separada o un solver CDCL.

1. Qué problema aborda

SAT pregunta si existe una asignación de valores booleanos que satisfaga simultáneamente todas las cláusulas de una fórmula CNF. SAT Engine permite estudiar distintas estrategias para encontrar asignaciones, comparar comportamiento en instancias generadas y observar cómo cambia la dificultad al variar la densidad de cláusulas.

3. Algoritmos

Backtracking

Explora sistemáticamente asignaciones y puede demostrar SAT o UNSAT cuando termina la búsqueda completa. El peor caso crece exponencialmente con el número de variables; es útil como referencia en instancias pequeñas.

GSAT

Parte de una asignación inicial y busca el flip de variable que maximiza el número de cláusulas satisfechas. Es una búsqueda local estocástica: puede encontrar una solución, pero quedarse atrapada en mínimos locales y no demuestra UNSAT si alcanza el límite de pasos.

WalkSAT

Selecciona una cláusula insatisfecha y, según el parámetro de ruido, elige un flip aleatorio o una variable con bajo breakcount. El breakcount mide cuántas cláusulas satisfechas pasarían a estar insatisfechas al invertir una variable. Tampoco demuestra UNSAT por agotar iteraciones.

Simulated Annealing y backend paralelo

La carpeta SAT_Engine_v5 documenta un backend C++ con GSAT, WalkSAT y Simulated Annealing, expuesto a Python mediante pybind11 y paralelizado con OpenMP. El wrapper ejecuta barridos de ratios m/n y múltiples instancias. La configuración de compilación publicada usa flags de MSVC (/O2, /openmp), por lo que no debe asumirse que compila sin ajustes en GCC/Clang.

4. Transición de fase y experimentación

El repositorio estudia instancias aleatorias 3-SAT variando el ratio α = m/n. La documentación señala el entorno α ≈ 4.267 como región crítica teórica de referencia y describe mediciones de proporción de instancias resueltas, tiempo y pasos. El README incluye una tabla ilustrativa de resultados de v3; no presenta allí los archivos crudos suficientes para tratarlos como un benchmark reproducible independiente.

La transición de fase es una propiedad estadística de familias de instancias aleatorias. El ratio m/n no permite clasificar con certeza una instancia individual como SAT o UNSAT ni determinar por sí solo su dificultad.

5. Cómo ejecutar

El repositorio publica Python 3.8+, compilador C++17 y OpenMP para el backend. Para las versiones Python:

git clone https://github.com/Hanzzel-corp/SAT-Engine-v7.git
cd SAT-Engine-v7
pip install -r requirements.txt
python sat_engine_v1.py
python sat_engine_v2.py
python sat_engine_v3.py
python sat_engine_v4.py

Para el backend C++ documentado:

cd SAT_Engine_v5
pip install pybind11
python setup.py build_ext --inplace
python sat_engine_v5.py

El ejemplo de backend usa hasta ocho hilos y 50.000 pasos por ejecución. Los comandos exactos y la compatibilidad deben comprobarse en el sistema operativo y compilador elegidos.

6. Cómo interpretar las salidas

  • Una asignación devuelta por un solver debe verificarse contra todas las cláusulas mediante el verificador.
  • Si GSAT o WalkSAT no encuentran solución dentro del límite de pasos, el resultado es “no encontrada”, no una prueba de UNSAT.
  • Una afirmación de UNSAT requiere un procedimiento completo y una ejecución terminada que permita justificarlo; los métodos locales descritos no bastan.
  • Para comparar rendimiento, fijar semillas, tamaño y distribución de instancias, límites de pasos, hilos, compilador y hardware.

7. Límites y discrepancias de documentación

  • El nombre v7 convive con documentación y carpetas de implementación hasta v5; no se afirma aquí que v7 sea un solver nuevo y completo.
  • El README contiene al final una línea de marcador de conflicto Git (>>>>>>>), señal de limpieza editorial pendiente.
  • La guía de arquitectura enumera DPLL/CDCL como extensiones futuras, no como funciones implementadas.
  • Los valores de transición de fase del README se presentan como resultados de referencia, pero esta ficha no ha reproducido esos ensayos.
  • La configuración de compilación del backend está orientada a MSVC y puede requerir cambios en otros toolchains.

English version · Technical project brief

SAT Engine: an evolving collection of SAT solvers

SAT Engine is a collection of Boolean satisfiability (SAT) generators and solvers. Its documented progression moves from exhaustive backtracking to stochastic local search and a parallel C++/Python backend.

Problem

SAT asks whether a Boolean assignment satisfies every clause in a CNF formula. The project provides implementations for exploring search strategies and observing how generated 3-SAT instances behave as the clause-to-variable ratio changes.

Documented implementations

  • v1: exhaustive backtracking and assignment verification.
  • v2: GSAT and WalkSAT local search.
  • v3: GSAT analysis and phase-transition experiments.
  • v4: restarts and adaptive noise.
  • v5: C++ backend with GSAT, WalkSAT and Simulated Annealing, exposed through pybind11 and parallelized with OpenMP.

The repository is named SAT-Engine-v7 and the runner prints “SAT Engine v7”, but its version table and code layout document implementations through v5. This page does not assume that a separate v6/v7 solver or CDCL implementation exists.

Algorithm semantics

Backtracking can complete an exhaustive search. GSAT flips variables to improve the number of satisfied clauses. WalkSAT selects an unsatisfied clause and uses a noise probability or breakcount-based choice. GSAT and WalkSAT are local-search methods: failure to find a solution within a step limit is not a proof of UNSAT.

Phase-transition experiments

The documentation studies random 3-SAT while varying α = m/n and uses α ≈ 4.267 as a critical-region reference. It describes measurements of solve rate, time and steps. The illustrative README table is not, by itself, a complete independently reproducible benchmark.

Reproduction

git clone https://github.com/Hanzzel-corp/SAT-Engine-v7.git
cd SAT-Engine-v7
pip install -r requirements.txt
python sat_engine_v1.py
python sat_engine_v2.py
python sat_engine_v3.py
python sat_engine_v4.py

For the documented C++ backend, install pybind11, enter SAT_Engine_v5, build with python setup.py build_ext --inplace, then run python sat_engine_v5.py. The published setup uses MSVC-specific compiler flags, so other toolchains may require adjustments.

Limitations

  • The v7 repository name coexists with code and documentation through v5.
  • The README contains an unresolved Git conflict marker near its end.
  • DPLL/CDCL is listed as future work, not as an implemented solver.
  • Local-search failure does not establish UNSAT.
  • This page does not claim to have reproduced the published phase-transition measurements.
